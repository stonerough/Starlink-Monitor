# Starlink Enhanced Monitoring & Outage Analytics

A robust, two-script Python system for Starlink users to monitor DNS connectivity and automatically **correlate outages with Starlink firmware updates** using gRPC. This solution provides clear, classified network performance metrics and intelligent uptime reporting.

---

## ⭐ Key Features

* **Intelligent Outage Classification:** Distinguishes between unscheduled ISP connectivity failure and scheduled downtime (firmware/maintenance).
* **Dual Monitoring:** Continuously checks multiple public DNS servers and polls the Starlink dish via local gRPC for status and version.
* **Automated Email Reporting:** Generates a daily uptime report (30-day view) classifying total downtime into Connectivity vs. Firmware-related minutes.
* **Systemd Integration Ready:** Designed for headless, service-based operation (`dns-monitor.service` file provided).
* **Log Rotation:** Includes log pruning functionality to prevent unbounded log file growth.

## 🛠️ Prerequisites

* A running **Starlink dish** accessible on your local network (default `192.168.100.1`).
* **Python 3.8+**.
* A **Gmail account** and a corresponding **App Password** for sending reports via SMTP.

## 🚀 Quick Start (Deployment on Linux)

### 1. Project Setup

```bash
# Clone the repository (or copy files)
git clone https://github.com/stonerough/Starlink-Monitor
cd Starlink-Monitor

# Create a Python Virtual Environment
python3 -m venv venv
source venv/bin/activate

# Install Dependencies
pip install -r requirements.txt

### 2\. Configuration (`.env` file)

Create a configuration file named **`.env`** in the project root based on the provided `.env.example`.

```env
# .env file content
SENDER_EMAIL=your_monitoring_email@gmail.com
SENDER_PASSWORD=your_gmail_app_password
RECIPIENT_EMAIL=your_report_recipient@example.com

# Optional: Adjust file paths and Starlink address if non-standard
# LOG_FILE_PATH=./data/monitordnsrelay.log
# STARLINK_VERSION_FILE=./data/starlink_version.json
# STARLINK_STATUS_URL=192.168.100.1:9200
```

***Note:** Replace `your_gmail_app_password` with the unique App Password generated in your Google Account security settings.*

### 3\. Running as a Service (`monitordnsrelay_service.py`)

To ensure continuous, background monitoring, use the provided `systemd` unit file (`dns-monitor.service`):

1.  **Modify the Service File:** Edit `dns-monitor.service` to correct the `User` and `WorkingDirectory` paths.
2.  **Install and Start:**
    ```bash
    # Copy the service file (assuming standard systemd path)
    sudo cp dns-monitor.service /etc/systemd/system/

    # Reload systemd manager configuration
    sudo systemctl daemon-reload

    # Enable and start the monitoring service
    sudo systemctl enable dns-monitor.service
    sudo systemctl start dns-monitor.service

    # Check status
    sudo systemctl status dns-monitor.service
    ```
    The service will now run continuously.

### 4\. Running the Reporter (`reportdnsrelay.py`)

The reporting script should be run **daily** via a cron job (e.g., midnight) to generate the report and prune logs.

```bash
# To open your crontab for editing:
crontab -e

# Example cron entry to run the report script daily at 00:05
05 00 * * * /path/to/starlink-enhanced-monitoring/venv/bin/python /path/to/starlink-enhanced-monitoring/reportdnsrelay.py > /dev/null 2>&1
```
